# تقدم تنفيذ منصة اليمن للجودة والاعتماد

## المرحلة الحالية

اكتملت المرحلة الأولى: الهوية والصلاحيات والهيكل المؤسسي.

اكتملت مرحلة إصدارات المعايير والمؤشرات ودورات التقييم.

اكتملت دورة العمل الأساسية من إدارة المؤسسات والمعايير حتى قرار الاعتماد.

المرحلة الحالية: الإكمال والتسليم والتحسينات التشغيلية.

## المنجز

- إنشاء تطبيق Laravel 12 وربطه بقاعدة MySQL باسم `yemen_qa`.
- ضبط اللغة العربية واتجاه واجهات المصادقة من اليمين إلى اليسار.
- إنشاء جداول الأدوار والصلاحيات وربطها بعلاقة متعدد إلى متعدد.
- إنشاء جداول الجامعات والكليات والأقسام والبرامج الأكاديمية.
- إنشاء تكليفات المستخدمين وربط الدور بنطاق الجامعة والكلية.
- إضافة حالة الحساب وإلزام تغيير كلمة المرور وتاريخ آخر دخول.
- إضافة سجل تدقيق لعمليات تسجيل الدخول والخروج.
- تنفيذ تسجيل الدخول باسم المستخدم أو البريد الإلكتروني والخروج الآمن.
- تنفيذ لوحة تحكم تتغير حسب الدور وتعرض نطاق التكليف والصلاحيات.
- إضافة بيانات تجريبية لجامعة صنعاء وثلاث كليات وقسم علوم الحاسوب وبرنامجه.
- إضافة اختبارات للمصادقة، الحساب الموقوف، نطاق الكلية، وحماية لوحة التحكم.
- إضافة صفحة إدارة المستخدمين وإنشاء الحساب والتكليف في معاملة واحدة.
- إضافة تفعيل وإيقاف الحسابات مع منع المسؤول من إيقاف حسابه الحالي.
- إضافة صفحة الهيكل المؤسسي لإنشاء الجامعات والكليات والأقسام والبرامج.
- تطبيق نطاق الجامعة على العرض والإضافة والتفعيل والإيقاف.
- منع مسؤول الجامعة من إدارة جامعة أخرى، وقصر تسجيل الجامعات على الإدارة المركزية.
- توحيد صفحات النظام في قالب Blade مشترك وقائمة تتغير حسب الصلاحية.
- إنشاء إصدارات مستقلة للمعايير بحالات: مسودة، معتمد، ومؤرشف.
- منع تعديل إصدار المعايير بعد اعتماده أو ربطه بدورة تقييم.
- التحقق قبل الاعتماد من أن مجموع أوزان المعايير 100% ومجموع مؤشرات كل معيار 100%.
- إضافة الإصدار الوطني الأول ويحتوي على تسعة معايير و18 مؤشرًا تتطلب أدلة.
- إنشاء دورات التقييم وربط كل دورة بإصدار معايير معتمد وثابت.
- تثبيت لقطة الجامعات والكليات المشاركة عند إنشاء الدورة حتى لا يتغير نطاقها لاحقًا.
- تطبيق مسار حالة الدورة: مسودة ثم مفتوحة ثم مغلقة للقراءة فقط.
- إضافة واجهات عربية فعلية لإدارة المعايير والمؤشرات ودورات التقييم حسب الصلاحيات.
- إعادة تصميم الواجهات بهوية بصرية موحدة، وتنقل بأيقونات، وبطاقات وجداول ونماذج محسنة، وقائمة متجاوبة للجوال.
- إنشاء التقويم الذاتي لكل كلية مشاركة في دورة تقييم مفتوحة.
- توليد استجابات جميع مؤشرات إصدار المعايير تلقائيًا عند بدء التقويم.
- إدخال درجات المؤشرات والملاحظات وحفظ العمل كمسودة.
- احتساب نتائج المعايير والنتيجة الكلية آليًا باستخدام أوزان المعايير والمؤشرات.
- تطبيق دورة عمل التقويم: مسودة، مرسل للمراجعة، معاد للتعديل، ومعتمد.
- إضافة شاشة للعميد لمراجعة تقرير الكلية واعتماده أو إعادته مع ملاحظات.
- عزل تقويمات الكليات ومنع أي مستخدم من الوصول إلى تقويم كلية أخرى.
- رفع الأدلة بصيغ PDF وWord وExcel والصور وتخزينها في مساحة خاصة غير عامة.
- ربط كل دليل باستجابة مؤشر محددة وتسجيل الاسم والحجم والنوع والبصمة الرقمية SHA-256.
- منع الملفات غير المسموحة أو الأكبر من 10 ميجابايت.
- إتاحة تنزيل الدليل للمستخدم المخول داخل الكلية نفسها فقط.
- تمكين العميد من قبول الدليل أو إعادته مع ملاحظة، ومنع اعتماد التقويم قبل قبول الأدلة المطلوبة.
- منع إرسال التقويم قبل إرفاق دليل صالح لكل مؤشر يتطلب دليلًا.
- إنشاء التقرير الجامعي فقط بعد اعتماد تقويمات جميع الكليات المشاركة في الدورة.
- تجميع متوسط نتائج الكليات وحساب نتيجة مستقلة لكل معيار ونتيجة كلية للجامعة.
- حفظ لقطة نتائج المعايير داخل التقرير لضمان ثبات التقرير المرسل.
- تمكين مسؤول الجامعة من كتابة الملخص التنفيذي والتوصيات وحفظ المسودة وتحديث التجميع.
- تطبيق دورة التقرير الجامعي: مسودة، مرسل للإدارة المركزية، معاد للتعديل، ومعتمد.
- عزل تقارير الجامعات ومنع مسؤول أي جامعة من الوصول إلى تقرير جامعة أخرى.
- إنشاء مهمة تقييم خارجي من التقرير الجامعي المعتمد وتعيين مقيم خارجي نشط لها.
- توليد نموذج درجات جميع المؤشرات تلقائيًا للمقيم وحساب نتائج المعايير والنتيجة الكلية بالأوزان.
- عرض مقارنة مباشرة بين نتيجة التقويم الذاتي والتقييم الخارجي والفارق بينهما.
- قصر وصول المقيم على المهام المسندة إليه ومنع المستخدمين غير المخولين من فتحها.
- تطبيق دورة التقييم الخارجي: مسند، مرسل للمراجعة، معاد للتعديل، ومعتمد.
- تمكين الإدارة المركزية من مراجعة التقييم الخارجي واعتماده أو إعادته بملاحظة.
- إنشاء خطة تحسين للكلية من التقويم الذاتي المعتمد وخطة للجامعة من التقييم الخارجي المعتمد.
- إضافة إجراءات التحسين وربطها بمعيار أو مؤشر مع وصف الفجوة والإجراء والمسؤول والأولوية والمدة.
- متابعة نسبة إنجاز كل إجراء وتغيير حالته تلقائيًا إلى مخطط أو قيد التنفيذ أو مكتمل.
- إظهار الإجراءات المتأخرة تلقائيًا عند تجاوز تاريخ الاستحقاق.
- تطبيق دورة الخطة: مسودة، فعالة، ومكتملة، ومنع إغلاقها قبل اكتمال جميع الإجراءات.
- تمكين الإدارة المركزية من متابعة جميع الخطط مع إبقاء التعديل لمالك نطاق الجامعة أو الكلية.
- إصدار قرار الاعتماد فقط من تقييم خارجي معتمد ومنع إصدار أكثر من قرار للتقييم نفسه.
- دعم قرارات الاعتماد الكامل والمشروط وعدم الاعتماد وتأجيل القرار، مع مدة السريان والشروط والمسوغات.
- إنشاء رقم قرار فريد وحفظ النتيجة النهائية والجهة المصدرة ووقت الإصدار.
- إضافة سجل قرارات يوضح القرار وحالته السارية أو المنتهية أو الملغاة.
- إنشاء تقرير نهائي قابل للطباعة يقارن نتائج المعايير الذاتية والخارجية ويعرض خطة التحسين المرتبطة.
- إتاحة إلغاء القرار بسبب إلزامي مع حفظ منفذ الإلغاء وتاريخه في سجل التدقيق.
- إضافة مركز إشعارات خاص بكل مستخدم مع عداد غير المقروء وروابط للمعاملة المرتبطة.
- إرسال إشعارات عند تسليم التقويم والتقرير والتقييم، وعند الإعادة أو الاعتماد، وعند تعيين المقيم وصدور القرار.
- إضافة شاشة سجل التدقيق مع التصفية حسب العملية والمستخدم وقصرها على المخولين.
- تطوير مؤشرات لوحة التحكم لعرض المهام التي تتطلب إجراء وخطط التحسين الفعالة حسب الدور.
- إعداد دليل عربي للتثبيت ودليل الاستخدام وقائمة فحص النشر والتسليم.

## حسابات التطوير

كلمة المرور المؤقتة لجميع الحسابات: `Demo@1234`

| اسم المستخدم | الدور |
|---|---|
| admin | مسؤول النظام التقني |
| central | الإدارة المركزية / هيئة الجودة |
| university | مسؤول الجودة الجامعي |
| college | مسؤول جودة الكلية |
| dean | العميد / الجهة المخولة |
| evaluator | المقيم الخارجي |

هذه حسابات تطوير فقط ويجب استبدالها قبل أي نشر فعلي.

## المتبقي في المرحلة الأولى

1. تعديل بيانات المستخدم وتغيير تكليفه وإعادة تعيين كلمة مروره.
2. تعديل أسماء ورموز عناصر الهيكل المؤسسي.
3. اختيار التكليف الفعال إذا امتلك المستخدم أكثر من دور.
4. شاشة تغيير كلمة المرور عند الدخول الأول.
5. طلبات إنشاء الحساب واستعادة الوصول.
